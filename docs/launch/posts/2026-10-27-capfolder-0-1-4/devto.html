Article

Originally published on capfolder.com.

Capfolder is an open-source (AGPL) cap table app built with Tauri and React. Your cap table lives in a folder of plain files on your own computer: an append-only, hash-chained events.jsonl in the Open Cap Format, plus your signed PDFs.

0.1.4 is about time: who owns what, and when. Here's how the pieces fit, in very little new math.

1. One vesting engine, every screen

The vesting math already existed: the golden tests check it to the share. The new Vesting screen, the person page and the Excel export's Overview and Vesting by month tabs all read from that one engine. None of them does its own math, so they can't disagree.

The graph shows the cliff, the monthly steps (or a straight line), today, and where vesting stops when someone leaves. The 409A price behind "vested value" is stored as an OCF VALUATION, not a setting.

2. The person page

Vested, next vest and fully vested moved next to the name. The graph went left, the holding and its history right, stacking on narrow windows. Y-axis labels got short (40K, 4M), which fixed labels being cut off.

3. Checking an import to the share

The last import step puts each total next to a box for the old tool's number. Fully diluted is required; each class, options outstanding, pool available, SAFE total and stakeholders are optional. If the file has a vested-so-far column, each grant is checked against our own schedule as of the export date:

const ours = vested === null ? null : vestedAt(qty, terms.get(key)!.data, start, p.exportDate).vested;
// 1 share of rounding allowed (tools round months differently)

More vested than granted blocks the import outright.

4. "What needs my attention?" without a model

Ask AI routes this one question to plain code before any model is called:

const ATTENTION = /needs? (my )?attention|what('s| is) urgent|what should i do/i;
// in askChat:
if (ATTENTION.test(question)) return attention(d);

attention() takes open and signed-but-not-wired envelopes, then the What's missing gaps (red first, grouped by kind), and keeps at most 3. Each Take me there target passes a whitelist: only certain screens, a person who exists, a row id that's a holding, a plan or an envelope.

5. A date bug

"As of" was set once, when the app opened. Leave it open overnight and a SAFE signed today was hidden behind yesterday's date. Now it follows the calendar (the founder's local day, not UTC) until you pick a date yourself.

What it doesn't do yet

The import check compares totals, not every row. The Before you cancel checklist asks you to check 3 people by hand.

The code is on GitHub. If you've built an app where several screens show the same numbers, how do you keep them from drifting apart?
