# 06 · AI (optional) — F-09, F-10, F-07 mapping, MCP

## Principle
AI only **proposes**. Rules and nearest-match run first; AI handles what's left; the founder confirms everything. This is the same pattern as the founder's expense-organiser project: rules → similar past items (kNN) → AI → review exceptions → every confirmation becomes a rule.

## Provider interface (`packages/ai`)
```ts
interface AIProvider {
  id: 'ollama' | 'lmstudio' | 'claude-cli' | 'codex-cli' | 'gemini-cli' | 'anthropic' | 'openai';
  local: boolean;                       // true = nothing leaves the machine
  available(): Promise<{ ok: boolean; detail?: string }>;
  extract<T>(input: { text: string; schema: JSONSchema; instructions: string }): Promise<T>; // schema-validated
  embed?(texts: string[]): Promise<number[][]>;   // for kNN; local providers only by default
  chat?(messages: Msg[], tools?: Tool[]): Promise<Msg>;
}
```

CLIs are spawned through the Tauri shell plugin, allow-listed binaries only, with a timeout, and the prompt is passed by stdin or file (never interpolated into a shell string).

## Privacy setting
"Allow cloud models to read document text" is **off** by default.
- **Off:** cloud providers can't do document extraction. They can still be used for chat over structured cap-table data (via MCP or the chat panel). Extraction falls back to a local model, or to "Needs you".
- **On:** document text may be sent to the chosen provider.

## Document sorting (F-09) pipeline
1. **Text:** PDF.js text layer. If empty, tesseract.js OCR.
2. **Classify:**
   - Rules first (rules pack: title regexes, required phrases, template fingerprints for the YC SAFE versions, 83(b), CIIAA, grant notice, board consent).
   - Then kNN over embeddings of confirmed docs: auto-assign if ≥4 of 5 neighbours agree.
   - Then AI classify.
3. **Extract:** `extract()` with the JSON schema for that doc type, e.g. SAFE = `{investor_name, amount, cap, discount, mfn, date, company_signed, investor_signed, pages:{field:page}}`.
4. **Match** to a cap-table row:
   - amount + date first (exact amount, date ±3 days);
   - then name similarity / email / aliases.
5. **Contradiction check:** if extracted fields differ from the matched row, it goes to "Needs you". Never auto-file.
6. **Learn:** a confirmation writes a local rule (alias, sender, template fingerprint).

## Terms diff (F-12)
- **YC-based paper:** normalize text (whitespace, quotes), diff against the matching YC template text, highlight changed spans in the viewer.
- AI summarizes each changed span into one plain line with its page number, labelled "AI summary, check the document".
- The founder ticks lines. Structured flags (`pro_rata`, `mfn`, `side_letter`, `custom_terms`) go on the `doc_added` event.

## Prompt-injection safety
- Document text is wrapped as data in the prompt.
- Outputs must validate against the JSON schema or are rejected.
- AI never triggers actions. It only fills a review form.

## MCP server (`packages/capfolder`, built; this section updated 2026-11-06)
- stdio transport; `npx capfolder mcp`. `npx capfolder install` wires Claude Code, Claude Desktop, Codex and Gemini CLI.
- Read tools (`tools/read.ts`): `list_companies`, `switch_company`, `get_cap_table(as_of?)`, `list_people`, `get_person(id)`, `get_vesting(id, as_of?)`, `get_gaps`, `list_documents`, `read_document(path)`, and `run_scenario` (what-ifs: founders, pool, SAFEs, priced rounds, exit, a default path with sources, sweeps; nothing written).
- Write tools (`tools/write.ts`): every one previews with `confirm: false` and records only with `confirm: true` plus the `preview_id` (docs/18 rule: AI proposes, the founder confirms).
- `run_scenario` is defined once in `tools/plans.ts` and shared with the desktop's Ask AI (docs/01, "Scenarios and the shared AI tools").
- The skill `skills/capfolder/SKILL.md` tells the model how to use them; `plugin/` and `GEMINI.md` carry identical copies.
