1. Bump the version in `apps/desktop/package.json`, `src-tauri/Cargo.toml` and `src-tauri/tauri.conf.json` (a test keeps them equal), and add a CHANGELOG entry.
2. Tag `vX.Y.Z` and push. `release.yml` builds a **draft** release with signed installers and `latest.json`.
3. Check the draft: `latest.json` must list `darwin-aarch64`, `darwin-x86_64`, `windows-x86_64` and `linux-x86_64` (the four jobs merge into it; a missing one means those users get no update). Then publish it. Installed apps pick it up within 6 hours, or on next open.

Rules pack: edit `rules/rules.json` (bump `version`), run `pnpm rules:sign`, commit both files. Apps fetch it from `raw.githubusercontent.com/MKBSP/capfolder/main/rules/` daily. Ruling: this replaces the release-tag delivery below, because GitHub release downloads send no CORS headers and raw does.

## 1. App updates (Tauri updater plugin)
- **Signing:** generate a key pair with the Tauri CLI. The public key goes in `tauri.conf.json`. The private key goes in CI secrets as `TAURI_SIGNING_PRIVATE_KEY`. **Back up the private key offline: losing it means existing installs can never be updated.**
- **Endpoint:** a static `latest.json` on GitHub Releases, generated by `tauri-action` in CI. Each platform entry has its `url` and `signature`.
- **Platform signing:** macOS apps are code-signed and notarized (Apple Developer ID); Windows installers are code-signed. Ship nothing unsigned.
- **Flow:** on open, `check()` runs. If there's an update, a toast says "Version x.y is ready · What changed". Then `downloadAndInstall()` and `relaunch()`.
- **Settings → Updates:** Automatic / Ask / Off. Off is fully supported. Automatic only *downloads*. Installing waits for "Restart now", because on Windows the installer closes the app.

## 2. Rules pack (signed JSON, hot-swapped)
**Holds:**
- export instructions per tool (markdown + image URLs);
- import detectors + column mappings;
- document-type rules and template fingerprints;
- check parameters;
- the template catalog (YC SAFE URLs + sha256);
- copy strings that may change.

**Format:**
```json
{
  "format": "capfolder-rules/1",
  "version": "2026.10.07-1",
  "min_app_version": "0.1.0",
  "export_guides": { "pulley": { "title": "Export from Pulley", "steps_md": "…", "images": [] }, "carta": {}, "cake": {} },
  "import_detectors": [ { "format": "pulley-detailed-xlsx", "match": { "sheetNames": [], "headerContains": [] }, "mapping": { "Source Header": "canonical.field" } } ],
  "doc_types": [ { "type": "safe_yc_postmoney_cap", "title_regex": "…", "required_phrases": [], "fingerprint_sha256": [], "schema": "safe" } ],
  "templates": [ { "id": "yc-safe-postmoney-cap", "source_url": "https://www.ycombinator.com/documents", "sha256": "…", "credit": "Y Combinator" } ],
  "checks": { "envelope_stale_days": 7, "eighty_three_b_days": 30 }
}
```

**Delivery:**
- `rules.json` + `rules.json.sig` (ed25519 / minisign) on GitHub Releases, under a `rules-latest` tag.
- The app checks daily, verifies the signature with the bundled public key, and swaps the pack in without a restart.
- A default pack is bundled in the app, so it works offline.

**Merge:** the user's local learned rules (aliases, mappings) live in app data and always override the pack.

## Event format changes
Never rewrite `events.jsonl`. Bump `format_version` in `capfolder.json` and append a `schema_migrated` event. The reducer understands all past versions. Old apps ignore unknown event types and show "Update to see everything".
