## M1 · `packages/core`
Pure TypeScript, no Node or Tauri I/O. Inputs are strings / parsed objects; outputs are values. Uses WebCrypto (`globalThis.crypto.subtle`), available in Node 22 and the Tauri webview.

Runtime deps: `canonicalize`, `ajv` (+ `ajv-formats` if the schemas need it), `ulid`. All MIT/Apache.

### Event log
- Envelope exactly as `docs/03`. `hash = sha256(JCS(event minus "hash"))`, `prev` = previous `hash`, `"0"×64` for seq 1.
- `verifyChain` reports the **first** failing line (1-based) and why: bad JSON, `prev` mismatch, `hash` mismatch.
- `appendEvent` refuses to return an event if: the chain is broken, an `ocf` event fails schema validation, or the resulting state fails an invariant. It returns `{ok:false, errors}` with plain-language reasons.
- Merge events with `prev: [a, b]` (docs/12 rule 4): `verifyChain` accepts an array `prev` structurally but M1 never produces one. ponytail: full fork merge is F-35, later.

### Fixture update
The Acme fixture has placeholder strings in `vesting_conditions` and `conversion_triggers`. Replace them with schema-valid OCF structures, then regenerate every `hash`/`prev` with `scripts/rehash-fixture.ts`. The numbers in `captable.expected.csv` must not change. Document in `fixtures/README.md` that hashes were regenerated and why.

### Reducer
1. Drop reversed events (`reversal.target`), apply `correction` events (field, new value) to their targets, in `seq` order.
2. Filter by `asOf`: OCF transactions by `data.date`; definitions (stakeholder, class, terms, issuer) always included; a stock plan only from its `board_approval_date`; app events by `ts` date. (Corrected 2026-10-10: filtering objects by `ts` hid stakeholders from any as-of before the day they were typed in.)
3. Sort transactions by (`data.date`, `ts`, `id`). Never by `seq`.
4. Apply: issuer, stakeholders, stock classes, plans (+ pool adjustments), vesting terms, stock issuances, equity comp issuances, vesting starts, convertible issuances, docs (`doc_added`, `doc_linked`, `doc_unlinked`, `doc_removed`), and the remaining M1 transactions: cancellation, return to pool, exercise, repurchase, convertible transfer, pool adjustment.
5. Unknown event types are kept but ignored; `State.unknownEventTypes` lists them ("Update to see everything").

### Derived numbers (all bigint, no floats)
- Outstanding per class = issued − repurchased − cancelled.
- Pool available = reserved + adjustments − granted + returned.
- FD = outstanding shares + options outstanding + pool available. SAFEs excluded.
- `fd_percent` = holding ÷ FD to 2 decimals, largest-remainder so rows sum to exactly 100.00. Ties broken by row order.
- SAFE `as_converted_percent` = amount ÷ post-money cap, 2 decimals, half-up. No cap → empty and "converts at next round".
- Every number has a `math` string, e.g. `3,000,000 = floor(4,000,000 × 36 ÷ 48), cliff passed 2024-10-07`.

### Vesting (option A, supported subset)
Supported OCF shape: one condition triggered by `VESTING_START_DATE`, followed by a chain of conditions with `VESTING_SCHEDULE_RELATIVE` triggers measured in months, each vesting a `portion` (numerator/denominator) or fixed `quantity`, with a `day_of_month` rule. Allocation `CUMULATIVE_ROUND_DOWN`. [verify field names against the vendored 1.2.0 schemas before coding]

Rule:
- m = whole months from start S to t. A month is complete on the same day of month; if that day doesn't exist, the last day of the month (OCF default).
- Sum the portions of all conditions whose relative trigger has been reached by m. With a cliff of 12/48 then 36 × 1/48 this is `min(m, 48)/48` once m ≥ 12, else 0.
- vested = floor(total × cumulative portion). Cumulative, so it never drifts.
- No `TX_VESTING_START` for a security with vesting terms → vested 0, gap "vesting not started".
- Any other shape (event triggers, absolute dates, other allocation types) → `unknown: true`, gap "vesting unknown", vested shown as empty. Acceleration and absolute schedules are added when an import needs them.

### Invariants (block the append)
1. Issued per class ≤ authorized. 2. Pool available ≥ 0. 3. Vested ≤ granted. 4. Exercised ≤ vested (unless early exercise is recorded). 5. Transfer/repurchase quantity ≤ current balance. 6. FD % rows sum to 100.00. 7. Every `doc_linked` target exists. (8, chain intact, is enforced by `appendEvent`.)

### Gaps (computed)
As `docs/03`: no linked signed document, 83(b) missing within 30 days, no IP assignment, grant without board consent, plan without documents, vesting unknown / not started, imported snapshot. Envelope staleness waits for M5 (no envelope events yet).

### `captable.csv`
- Header and columns exactly as `docs/03` / the fixture. LF line endings, trailing newline, no quoting unless a field contains `,` `"` or newline (RFC 4180).
- Row order: stock holdings, then options, then the pool row, then SAFEs. Within a group: by issue date, then security id. Record this rule in `docs/03-data-model.md`.
- `doc_status`: `signed` if any `doc_linked` targets the security, else `missing`. Pool row empty.

### `ocf/` export
OCF manifest + one file per object type (stakeholders, stock classes, plans, vesting terms, transactions), derived from events after corrections/reversals; `DOCUMENT` objects from `doc_*` events. Validated with the same ajv validator in tests. Round-trip import is M6.

## Testing
- `chain.test.ts`: the Acme chain verifies; mutating any single line (each of the 29) fails at exactly that line.
- `golden.test.ts`: `toCaptableCsv(reduce(acme, "2026-10-07"))` === `captable.expected.csv` bytes.
- `vesting.test.ts`: cliff on the 31st (→ Feb 28/29), before / exactly at / after cliff, full vest at 48, never exceeds total.
- `reduce.test.ts`: edge cases from `docs/09`: termination before cliff, partial SAFE transfer, exercise then repurchase, pool increase, correction + reversal, as-of before/after each event.
- `invariants.property.test.ts`: fast-check generates 10k valid event sequences; invariants hold and the FD % sum is 100.00 for each.
- `ocf.test.ts`: every OCF payload in the fixture validates; the `ocf/` export validates.
